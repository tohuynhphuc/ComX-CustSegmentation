\chapter{System Integration, Verification and Limitations}\label{chap:integration}

\section{End-to-End System Integration}
The completed Business Intelligence solution establishes an automated pipeline connecting operational transactions in \texttt{CompanyX} to an analytical data warehouse, predictive machine learning models, and interactive reporting dashboards. 

The architecture balances operational responsiveness with historical depth:
\begin{itemize}
    \item \textbf{Operational Path (\texttt{FactCustomerRFMLive}):} Incremental SSIS packages capture demographic modifications and sales transactions at one-minute intervals. The Python scoring engine applies active centroid parameters from \texttt{DimModelConfig} to reclassify affected buyers immediately upon purchase.
    \item \textbf{Historical Path (\texttt{FactCustomerSnapshot}):} Monthly scheduled routines compute standardized 365-day RFM snapshots as of each calendar month-end date, enabling longitudinal cohort analysis, inactivity tracking, and annual model recalibration.
\end{itemize}

\section{Execution Schedule and Orchestration}
The operational jobs run under automated schedules:
\begin{itemize}
    \item \textbf{High-Frequency Micro-Batch (1-minute interval):} Deployed SSIS packages poll the operational database for changes using watermark timestamps: \texttt{Package\_Customer\_}\allowbreak\texttt{Incremental.dtsx} and \texttt{RFM\_Live.dtsx}.
    \item \textbf{Monthly Snapshot (00:05 on the 1st of each month):} Package \texttt{RFM\_Snapshot.dtsx} computes customer states for the preceding month-end.
    \item \textbf{Annual Model Retraining (1 January):} The Apache Airflow DAG \texttt{rfm\_}\allowbreak\texttt{year\_}\allowbreak\texttt{end\_}\allowbreak\texttt{training} is configured to retrain cluster centroids on completed annual snapshots and register new model versions in \texttt{DimModelConfig}.
\end{itemize}

\section{System Verification and Quality Assurance}
To ensure reproducibility and analytical consistency, multiple automated and SQL-based verification checks were implemented:
\begin{enumerate}
    \item \textbf{Demographic Integrity:} Verified that current customer counts in \texttt{DimCustomerProfiling} match source individual customer counts, and that historical profile changes are correctly versioned with effective date intervals in \texttt{DimClusterProfiling}.
    \item \textbf{Snapshot Uniqueness:} Validated that each customer possesses at most one record per monthly snapshot date in \texttt{FactCustomerSnapshot}, with zero duplicate primary keys.
    \item \textbf{Model Parameter Consistency:} Confirmed that each retrained model version saved in \texttt{DimModelConfig} contains exactly five cluster centroid definitions with valid scaling parameters and active date ranges.
    \item \textbf{Data Reconciliation:} Provided the verification script \texttt{VERIFY\_}\allowbreak\texttt{BUSINESS\_}\allowbreak\texttt{FIGURES.sql} to audit key baseline metrics, including customer counts (18,485), aggregate spend (\$15.46M), and cluster demographic statistics across the pipeline.
\end{enumerate}

\section{Operational Limitations and Future Considerations}
\begin{itemize}
    \item \textbf{Purchase-Time Recency Semantics:} By design, \texttt{FactCustomerRFMLive} sets recency to zero on purchase date. Consequently, tracking progressive customer inactivity requires consulting the monthly \texttt{FactCustomerSnapshot} table.
    \item \textbf{Airflow Sensor Dependency:} In a production environment, adding an explicit SQL sensor task to the Airflow DAG to verify that the SSIS December snapshot has fully committed before model training begins will ensure robust unattended execution.
    \item \textbf{Online Cloud Deployment:} The current system is successfully deployed in an on-premises development environment. Migrating the SQL Server warehouse and Power BI reports to Azure Synapse or Fabric represents an ideal next step for enterprise-scale distribution.
    \item \textbf{Empirical Campaign Validation:} While the dashboard provides actionable decision support, proving causal revenue lift requires executing live marketing campaigns with randomized holdout control groups.
\end{itemize}
