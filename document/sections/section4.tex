\section{The General View}
Figure~\ref{fig:system_workflow} summarizes the two complementary data paths and annual model training. The customer-demographics load and purchase-triggered RFM path support operational decisions; the monthly snapshot path preserves the state of customers at a common evaluation date.

\begin{figure}[htbp]
    \centering % Căn giữa hình ảnh
    \includegraphics[width=0.8\textwidth]{finalSystemWorkflow.png}
    \caption{High-level flow from CompanyX transactions to RFM facts, model configurations, and reporting.}
    \label{fig:system_workflow} % Nhãn để dùng cho lệnh tham chiếu \ref{}
\end{figure}

The first path processes customer transactions operationally. Deployed SSIS packages execute every minute to detect newly modified customer profiles and calculate purchase-time RFM metrics for affected buyers in \textbf{FactCustomerRFMLive}. A Python scoring script (\texttt{live\_clustering.py}) applies the active parameters from \texttt{DimModelConfig}, standardizes the features, and assigns the customer to the closest cluster centroid in standardized RFM space. Because this operational view evaluates metrics at the customer's latest purchase event, it provides an immediate post-transaction classification.

The second path executes on a monthly schedule (00:05 on the first day of each month) to compute RFM states as of the \emph{previous month-end date} and appends them to \textbf{FactCustomerSnapshot}. This monthly table tracks customer dormancy over time and serves as the training source for annual K-Means model retraining.

For model initialization, \texttt{bootstrap.py} established the baseline 2011 model from year-end data, followed by annual retraining models for 2012 and 2013 using \texttt{train\_model.py}. The Power BI dashboard presented in Chapter~\ref{chap:power_bi} utilizes the 30 June 2014 snapshot as its primary reporting reference.

\section{ETL Pipeline \& Data Flow}
This section follows the three SSIS packages supplied in the project: \texttt{Package\_Customer\_}\linebreak[1]\texttt{Incremental.dtsx}, \texttt{RFM\_Live.dtsx}, and \texttt{RFM\_Snapshot.dtsx}. The following screenshots and SQL excerpts are from the team's implementation; full routine definitions are included in the system resources. The customer and live packages have been deployed on a one-minute schedule, while the snapshot package is scheduled monthly.

Overall, there are three primary components in this data flow:
\begin{itemize}
    \item \textbf{vPersonDemographics (OLE DB Source):} Extracts changed demographic records from the CompanyX operational database:
    \begin{lstlisting}[caption={Table Selection}, label={lst:tab_select}]
SELECT
    c.CustomerID AS CustomerKey,
    d.BusinessEntityID,
    CAST(d.BirthDate AS DATE) AS BirthDate,
    d.Gender,
    d.MaritalStatus,
    d.YearlyIncome,
    d.TotalChildren,
    d.Education,
    d.Occupation,
    CAST(d.HomeOwnerFlag AS TINYINT) AS HomeOwnerFlag,
    d.NumberCarsOwned,
    CAST(d.DateFirstPurchase AS DATE) AS DateFirstPurchase,
    st.[Name] AS CountryName,
    st.[Group] AS RegionGroup
FROM Sales.vPersonDemographics AS d
INNER JOIN Sales.Customer AS c
    ON d.BusinessEntityID = c.PersonID
LEFT JOIN Sales.SalesTerritory AS st
    ON c.TerritoryID = st.TerritoryID
LEFT JOIN CompanyX_DataWarehouse.dbo.DimCustomerProfiling AS dc
    ON dc.CustomerKey_Str = CONVERT(NVARCHAR(20), c.CustomerID)
LEFT JOIN CompanyX_DataWarehouse.dbo.DimClusterProfiling AS dp
    ON dp.CustomerKey_Str = CONVERT(NVARCHAR(20), c.CustomerID)
   AND dp.IsCurrent = 1
WHERE d.DateFirstPurchase IS NOT NULL
  AND (
       dc.CustomerKey_Str IS NULL
       OR dp.CustomerKey_Str IS NULL
       OR EXISTS (
           SELECT d.Gender, d.MaritalStatus, d.TotalChildren,
                  CONVERT(BIT, d.HomeOwnerFlag), d.NumberCarsOwned
           EXCEPT
           SELECT dc.Gender, dc.MaritalStatus, dc.TotalChildren,
                  dc.HomeOwnerFlag, dc.NumberCarsOwned
       )
       OR EXISTS (
           SELECT d.YearlyIncome, d.Education, d.Occupation,
                  st.[Name], st.[Group]
           EXCEPT
           SELECT dp.YearlyIncome, dp.Education, dp.Occupation,
                  dp.CountryName, dp.RegionGroup
       )
  );
    \end{lstlisting}
    The extraction selects customers with a first purchase whose relevant demographic attributes are missing or different from the warehouse’s current values. The \texttt{EXCEPT} predicates compare groups of attributes, including nullable values, performing change detection without requiring a complete reload on every execution.

    \item \textbf{Derived Column Transformation:} Normalizes input values and standardizes missing demographic attributes before staging, assigning configured fallback defaults (such as \texttt{"Unknown"}, \texttt{0}, and \texttt{"U"}) as shown in Figure~\ref{fig:derived_col}.

    \item \textbf{stg Customer Profile (OLE DB Destination):} Writes the transformed records directly into the staging table (\texttt{stg.CustomerProfile}, described in Section~\ref{subsec:stg_tab}) ready for the subsequent T-SQL merge.
\end{itemize}

\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.85\textwidth]{DerivedColumn.png}
    \caption{Derived Column: input data cleaning step.}
    \label{fig:derived_col}
\end{figure}

Finally, the \emph{Apply Customer Merge} SQL task executes the batch procedure if rows were staged. That procedure applies Type 0/1 customer rules and Type 2 demographic history in a transaction:
\begin{lstlisting}[caption={Merge}, label={lst:merge}]
DECLARE @BatchID UNIQUEIDENTIFIER = CONVERT(UNIQUEIDENTIFIER, ?);
IF EXISTS (
    SELECT 1
    FROM stg.CustomerProfile
    WHERE BatchID = @BatchID
)
BEGIN
    EXEC dbo.usp_ApplyCustomerProfileBatch @BatchID = @BatchID;
END;
\end{lstlisting}

The first SSIS task, \emph{Refresh Customer RFM Live}, calls \texttt{usp\_RefreshCustomerRFMLive}. A database watermark tracks the last processed order modification timestamp. When new or updated sales transactions are detected, the procedure recalculates order frequency and monetary totals for the affected customers and merges the results into \texttt{FactCustomerRFMLive}.

The second task, \emph{Score Live Customers}, runs the Python scoring script \texttt{live\_}\allowbreak\texttt{clustering.py}. It reads the latest active cluster centroids from \texttt{DimModelConfig}, standardizes the customer's RFM vector, and updates the segment label. Scheduled to run at one-minute intervals, this micro-batch pipeline delivers near-real-time customer segmentation.

The first task, \emph{Append Monthly Customer Snapshot}, determines the previous month-end and calculates historical RFM values for the \textbf{FactCustomerSnapshot}:
\begin{lstlisting}[caption={Monthly RFM Calculation}, label={lst:month_RFM}]
DECLARE @SnapshotDate DATE;

SET @SnapshotDate = EOMONTH(GETDATE(), -1);

EXEC dbo.usp_AppendMonthlyRFMSnapshot
    @SnapshotDate = @SnapshotDate;
\end{lstlisting}

The subsequent \emph{Cluster Snapshot} task assigns segment labels using the available effective-dated model definitions:
\begin{lstlisting}[caption={Monthly Cluster Segment}, label={lst:month_cluster}]
EXEC dbo.usp_ClusterCustomerRFMSnapshot;
\end{lstlisting}

\section{Annual Model Training and Scheduling}
The annual retraining workflow utilizes the year-end customer snapshot as training data to recalibrate cluster centroids. Following the initial 2011 bootstrap model, models for 2012 and 2013 were trained using \texttt{train\_model.py}, with the resulting centroids and scaling parameters stored into \texttt{DimModelConfig}.

To automate future retraining, the Apache Airflow DAG \texttt{rfm\_year\_end\_}\allowbreak\texttt{training} is configured to trigger on 1 January following the completion of the December snapshot, ensuring seamless annual model updates.

\section{Pipeline Outputs}
In summary, the automated ETL pipeline produces:
\begin{enumerate}
    \item Current demographic profiles in \texttt{DimCustomerProfiling} (Type 1) and historical version tracking in \texttt{DimClusterProfiling} (Type 2);
    \item Near-real-time operational segmentation in \texttt{FactCustomerRFMLive} triggered by incoming transactions;
    \item Comprehensive monthly historical records in \texttt{FactCustomerSnapshot} for longitudinal analysis;
    \item Versioned machine learning configurations in \texttt{DimModelConfig}.
\end{enumerate}
This architecture provides the complete data foundation for the Power BI dashboards discussed in Chapter~\ref{chap:power_bi}.
